# QQ 聊天机器人 · 另一台电脑部署指南

> **版本基线：2026-10-26**
> 本文按本机当前真实状态整理，目标是换一台 Windows 电脑后能独立复现：
> QQ 小号 ↔ SnowLuma ↔ qq-bridge ↔ DeepSeek Harness（DSH），可选接入 A绘世画图、GPT-SoVITS 语音。
>
> 旧的 `部署说明.md` 是 2026-10-24 的历史版本（里面还有“开机自启”“群白名单 <GROUP_QQ>”“语音画图未安装”等旧信息），**以本文为准**。

---

## 0. 先看结论（TL;DR）

本次部署由 4 个核心部分组成：

```text
QQ 小号（QQNT）
   │  SnowLuma 注入 QQ，提供 OneBot v11
   ├─ HTTP 127.0.0.1:3000
   └─ WS   127.0.0.1:3001
          ↓
qq-bridge（Node，控制台 127.0.0.1:3100）
   │  把 QQ 消息转成 DSH prompt，把 DSH 回复发回 QQ
   ↓
DeepSeek Harness（DSH 桌面版，Web API 端口动态）
   ├─ agent preset：qq-chat / qq-chat-v2
   ├─ MCP：mcp-snowluma / mcp-snowluma-host / mcp-web-search-safe
   ├─ 可选：A绘世 API 127.0.0.1:7860（画图，按需启动）
   └─ 可选：GPT-SoVITS API 127.0.0.1:9880（语音，按需启动）
```

**关键结论：**

- 必装：DSH、QQ NT、SnowLuma、qq-bridge。
- 可选：A绘世 + Animagine XL（画图）、GPT-SoVITS（文字转语音）。
- **本指南不包含**：ComfyUI、Qwen Image 改图、ACE-Step 作曲、RVC 声模转换、UVR5 API、音乐生成。这些在本机没有部署/没有验收；UVR5 只是 GUI 程序，不是本地 API。
- 当前账号：QQ 小号 `<BOT_QQ>`；主人/唯一白名单 `<OWNER_QQ>`；群白名单为空。
- 当前**没有开机自启 QQ 机器人**；开机只启动 DSH，机器人靠开始菜单「启动 QQ 机器人」手动启动。
- **新电脑不要只 `npm install` 上游 qq-bridge**：本机 qq-bridge 有大量本地改动（画图、TTS、群聊策略、按需生命周期）。最稳的是**把本机 `DSH-QQ-bridge` 整个目录复制过去**，再改路径/令牌。
- `config.json` 含 SnowLuma / 控制台令牌；备份和复制时不要外传，换机后建议换新令牌。
- 当前 `config.json` 的 DSH 端口是动态同步的，不要把它写死成某一台机器的端口。

## 3. 账号、白名单与安全

### 3.1 账号

- QQ 机器人小号：`<BOT_QQ>`
- 主人 QQ（owner）：`<OWNER_QQ>`
- 当前私聊白名单：`[<OWNER_QQ>]`
- 当前群白名单：`[]`（空）
- 当前群聊唤醒：被 @、叫名字/关键词（`<PERSONA_ALT>` / `<PERSONA_ALT2>` / `<PERSONA_NICK>`）、被拍一拍（只认拍机器人本人）
- 当前模式：`reserved2`（二代仿真）
- 当前角色：`<PERSONA>`（`roles/<PERSONA>.md`）

> 不要主动改白名单。要加人/加群，先在控制台「访问与安全 → 白名单」确认后再保存；保存是热生效，不用重启桥接。

### 3.2 安全

- `config.json` 含：
  - `consoleToken`（qq-bridge 控制台）
  - `snowluma.accessToken`（OneBot 鉴权）
  - DSH 的 Cookie/会话凭据（桥接自己维护）
- 不要把 `config.json` 发到公开仓库/群聊；备份到 E 盘也要注意保密。
- 换电脑后建议重新生成控制台令牌/SnowLuma token；不要直接沿用旧令牌。
- 桥接默认只监听本机；不要把 3100/5099/3000/3001 映射到公网。

## 4. 新电脑前置条件

1. Windows 10/11 x64，建议 16GB 内存。
2. 安装 **QQ NT**，登录机器人小号 `<BOT_QQ>`；主人号不要登录在这台机（本机 SnowLuma 已打补丁，只自动加载小号；但少一个登录少一份风险）。
3. 安装 **DSH 桌面版**，登录 DSH，确认能正常打开 Web UI、模型能对话。
4. 安装 **SnowLuma 1.14.20**（完整包，带 `launcher.bat`），首次启动按它自己的 EULA/隐私政策人工确认。
5. 准备 **Node.js >= 22.13**：
   - 最省事：复用 DSH 自带 Node（本机 `v24.21.0`）；
   - qq-bridge 需要 `npm`，如果 DSH 自带 Node 目录没有 npm，先用 npmmirror 引导 npm。
6. 可选安装：A绘世（画图）、GPT-SoVITS（语音）、7-Zip。
7. 网络：
   - 本机 GitHub 被 hosts 指到 `127.0.0.1`，直连失败；
   - 可用镜像：`https://gh-proxy.com/`、`https://registry.npmmirror.com`、`https://hf-mirror.com`、ModelScope、PyPI；
   - 另一台电脑网络正常的话可以直连，但下载大模型建议仍用镜像。

## 5. 安装 qq-bridge

### 5.1 推荐：直接复制本机整个目录

因为本机 qq-bridge 不是纯上游版本，包含：

- `src/ai-image.js`：A绘世画图客户端 + 空闲卸载/停进程
- `src/tts-core.js`：GPT-SoVITS TTS 客户端 + 按需启动
- `src/bridge.js`：画图/发图/TTS 路由、群聊强制策略、拍一拍只认本人、出站记录等
- `src/mcp-snowluma-safe.js`：`qq_generate_image`、`qq_send_image`、`qq_tts` 等工具
- `scripts/start-ai-api.cmd`、`stop-ai-api.cmd`、`start-tts-api.cmd`、`stop-tts-api.cmd`
- `scripts/sync-dsh-now.ps1`、备份脚本
- `start-bot.cmd` / `stop-bot.cmd`
- `roles/<PERSONA>.md`

**复制建议：**

```text
复制：src\  scripts\  roles\  package.json  package-lock.json
      config.json（或 config.example.json 重新配置）
      start-bot.cmd  stop-bot.cmd  start-bridge.cmd  stop-bridge.cmd
      restart-bridge.cmd  start.bat  .npmrc
不复制：node_modules\（到新机重装）
        tools\（junction，到新机重建）
        data\generated\（生成图，可选）
        state\（会话/社交状态，迁移记忆请走 E 盘备份恢复）
        logs/临时文件
```

> 如果只从 GitHub 克隆上游，画图/TTS/群聊策略都没有，需要重新打补丁；不推荐。

### 5.2 准备 Node 与依赖

把 qq-bridge 放到新电脑，例如：

```text
<DSMP_BRIDGE_DIR>
```

在目录中打开 PowerShell/CMD：

```bat
cd /d "<DSMP_BRIDGE_DIR>"
set PATH=<DSMP_BRIDGE_DIR>\tools\node-runtime\bin;%PATH%
npm install --registry=https://registry.npmmirror.com
```

`npm install` 会执行 `postinstall`（`scripts/patch-snowluma-sdk.mjs`），修补 SnowLuma SDK；如果失败，看 §14。

### 5.3 重建 ASCII junction

本机 `tools\node-runtime` 指向 DSH 自带 Node，`tools\dsh-app` 指向 DSH 安装目录。新电脑路径不同，需要重建：

```bat
cd /d "<DSMP_BRIDGE_DIR>"
rmdir tools\node-runtime
rmdir tools\dsh-app
mklink /J tools\node-runtime "C:\Users\<用户名>\.dsh\...\node"
mklink /J tools\dsh-app "D:\...\DeepSeekHarness"
```

实际 Node 路径以 DSH 安装目录为准；如果找不到，用：

```powershell
Get-ChildItem 'C:\Users\<用户名>\AppData\Local\Programs' -Recurse -Filter node.exe -ErrorAction SilentlyContinue
```

本机实际目标（供参考）：

```text
tools\node-runtime → <LOCAL_TOOLS>\tools\DeepSeekHarness\resources\runtime\primary-runtime\dependencies\node
tools\dsh-app      → <LOCAL_TOOLS>\tools\DeepSeekHarness
```

> 如果不想用 junction，也可以直接改 `start-bridge.cmd`、`scripts\autostart-qqbot.ps1`、`scripts\sync-dsh-now.ps1` 里的 `$node` / `node` 路径。

### 5.4 自检

```bat
tools\node-runtime\bin\node.exe src\self-test.js
```

或：

```bat
npm run self-test
npm run verify:adaptation
```

先不要急着启动；先把 §6 DSH、§7 SnowLuma 配好。

## 6. 配置 DSH（preset + MCP）

### 6.1 安装 agent presets / MCP

```bat
cd /d "<DSMP_BRIDGE_DIR>"
tools\node-runtime\bin\node.exe scripts\setup-dsh.mjs desktop
```

说明：

- `desktop` 是本机 DSH profile 名；另一台电脑可能是 `web`，用实际 profile 名替换。
- 脚本会：
  - 安装/更新 `qq-chat`、`qq-chat-v2` 两个 agent preset；
  - 在 DSH profile 的 `cordis.patch.yml` 挂载：
    - `mcp-snowluma`
    - `mcp-snowluma-host`
    - `mcp-web-search-safe`
  - 注册 `qq-mode-console`、`qq-agent-presets` 两个 bundle；
  - 覆盖前自动备份 profile 文件。
- **跑完重启 DSH**，让 MCP/preset 生效。
- DSH 的 MCP 子进程在启动时注册工具；以后改 `src/mcp-snowluma-safe.js` 或工具描述，**必须重启 DSH** 才会出现新工具。

### 6.2 DSH 模型与 profile

本机配置：

- provider：`deepseek-official`
- model：`deepseek-flash`
- reasoningEffort：`high`
- profile：`desktop`

换电脑后在 DSH 设置里选自己的可用模型即可；桥接 `config.json` 的 `dsh.provider` / `dsh.model` 要与 DSH 实际配置一致。

### 6.3 DSH 端口

DSH 桌面版每次启动的 Web 端口可能变化（本机当前 `54973`，不要写死）。桥接用：

```bat
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\sync-dsh-now.ps1
```

自动探测 DSH 主进程监听端口并写回 `config.json` 的 `dsh.baseUrl`。

> 直接 `curl` DSH API 返回 401 是正常的：桥接会自己 mint Cookie；不要因为 401 就以为 DSH 没配好。

## 7. 配置 SnowLuma

### 7.1 首次启动

1. 双击：

```text
<LOCAL_TOOLS>\SnowLuma\launcher.bat
```

2. 终端会打印 WebUI 地址（默认 `http://127.0.0.1:5099`）和初始密码。
3. 浏览器打开，按提示完成 EULA/隐私政策（只能本人确认）。
4. 用 `admin` + 终端密码登录。

### 7.2 节点配置

在 SnowLuma 左侧「节点配置」：

- 开启 **HTTP API**（默认 `3000`）
- 开启 **WS 客户端/服务端**（默认 `3001`）
- accessToken 可以留空；桥接会从 SnowLuma 配置自动读取并回写。
- 如果端口被占用，改端口后同步改 `config.json` 的 `snowluma.wsUrl` / `httpUrl`。

### 7.3 自动注入 QQ（已打补丁）

本机已给 SnowLuma 打了“只注入小号”的补丁：`hookAutoLoad=true`，但启动时先探测 QQ 进程的 UIN，只有 `<BOT_QQ>` 会被自动加载；`<OWNER_QQ>` 会被跳过。

补丁文件：

```text
<DSMP_BRIDGE_DIR>\scripts\patch-snowluma-autoload-target.mjs
```

换机或 SnowLuma 升级后执行一次（升级会覆盖 `index.mjs`）：

```powershell
& "<LOCAL_TOOLS>\SnowLuma\node.exe" "<DSMP_BRIDGE_DIR>\scripts\patch-snowluma-autoload-target.mjs"
```

它会备份 `index.mjs`，写入目标 UIN 过滤逻辑，并把 `config\runtime.json` 的 `hookAutoLoad` 设为 `true`。

正常启动后：

1. 先登录 QQ 小号 `<BOT_QQ>`。
2. 启动 SnowLuma；日志出现 `login detected: PID=... UIN=<BOT_QQ>`，随后 3000/3001 监听。
3. 不需要再手点「加载」。

手动兜底：如果日志里没有自动加载（QQ 登录太慢/补丁未生效），到 SnowLuma →「进程注入」找到 `UIN=<BOT_QQ>` 点「加载」；**不要加载 <OWNER_QQ>**。

> QQ 重启后 PID 会变；补丁会在发现新进程后探测 UIN 并自动加载，不需要手动改 PID。
> 注意：QQ 进程里已注入的旧 hook 在 SnowLuma 重启后会直接重连；这是正常现象，不代表跳过了自动加载逻辑。

### 7.4 SnowLuma 启动/停止

```bat
<LOCAL_TOOLS>\SnowLuma\launcher.bat
<LOCAL_TOOLS>\SnowLuma\stop-snowluma.cmd
```

自动启动脚本 `start-snowluma-autostart.cmd` 本机存在，带 10 秒重启循环；`start-bot.cmd` 也用它启动 SnowLuma，二者都会触发已打补丁的“只加载 <BOT_QQ>”自动注入。

### 8.1 角色与模式

- 角色卡：`roles/<PERSONA>.md`
- 控制台：`http://127.0.0.1:3100`
- 登录后：
  - 模式选 `reserved2`（二代仿真）
  - 角色选 `<PERSONA_ALT>`
  - 白名单只留 `<OWNER_QQ>`
  - 群白名单保持空
- 角色卡最多注入 `role.maxInjectChars=6000` 字符；`<PERSONA>.md` 是提炼版，原始 docx 保留在根目录作权威源。

### 8.2 群聊规则（本地补丁，升级要留意）

本机群聊是“克制参与”策略：

- 只在被 @、叫名字/关键词（<PERSONA_ALT>/<PERSONA_ALT2>/<PERSONA_NICK>）、拍一拍（只认拍机器人本人）时参与；
- 关闭提问唤醒、随机概率、anyMessage、群主动机会；
- 私聊保持活跃；
- 强制策略由本地补丁实现：
  - `src/bridge.js` 的 `scheduleProactiveCheckV2` 对 `group:` 直接跳过；
  - `/api/socialV2/wake-config` 里的 `groupTriggerOnly` 分支强制收回；
  - `handlePokeNotice` 只认 `targetIsSelf`；
- 升级/重装上游 qq-bridge 会覆盖这些补丁；升级前备份 `src/bridge.js`，升级后对比。

## 9. 启动顺序与日常使用

### 9.1 推荐：开始菜单

本机开始菜单有：

- 「启动 QQ 机器人」→ `start-bot.cmd`

### 13.2 常见问题

| 症状 | 先查 | 处理 |
|---|---|---|
| QQ 发消息不回复 | 桥接 3100、DSH 端口、SnowLuma online | 看控制台“运行总览”；`sync-dsh-now.ps1`；重启桥接 |
| SnowLuma 识别不到小号 | QQ 是否登录小号、SnowLuma 日志是否有 auto-load | 先看 `snowluma-*.log` 的 `auto-load`/`login detected`；补丁未生效时重跑 `scripts\patch-snowluma-autoload-target.mjs`；兜底手动加载 `UIN=<BOT_QQ>` |
| QQ 重启后不回复 | SnowLuma 是否自动接新 PID | 看 SnowLuma 日志；补丁会探测 UIN 自动加载；失败再手动点“加载”；桥接会自动重连 |
| 画图提示“无法连上画图引擎” | 7860 是否监听 | 点「启动画图引擎」；首次冷启动 40–70 秒；查 `ai-api.log` |
| 画图很慢/爆显存 | 是否 8GB、是否同时跑语音 | 用 `--medvram`；不要同时跑 GPT-SoVITS GPU 版；降低分辨率/步数 |
| 画图生成失败 | 模型名、A绘世模型目录 | 确认 Animagine 文件存在；`/sdapi/v1/options` 的 checkpoint |
| 语音没声音/超时 | 9880、参考音频、`api.log` | 手动 `start-tts-api.cmd`；检查 ref 路径/文本；v1 CPU 配置 |
| MCP 工具列表没有新工具 | DSH 是否重启 | 改 `mcp-snowluma-safe.js`/工具描述后必须重启 DSH |
| 桥接启动失败 | Node 路径、3100 占用、config JSON | 看 `state\` 日志；`node --check`；端口冲突 |
| 控制台登录失败 | `consoleToken` | 用 config 当前值；改后重启/热生效视实现 |
| 群聊太吵 | `groupTriggerOnly` | 确认 `config.socialV2.wake.groupTriggerOnly=true`；升级后补丁可能被覆盖 |
| DSH 端口变了 | `config.dsh.baseUrl` | 跑 `scripts\sync-dsh-now.ps1`，再 `restart-bridge.cmd` |
| GitHub 下载失败 | 网络 | 用 `gh-proxy.com` 前缀、npmmirror、hf-mirror |
| 中文路径/空格导致批处理失败 | `.cmd` 编码/路径 | 用 junction 到 ASCII 路径；路径加引号；PowerShell 脚本保留 UTF-8 BOM |
| A绘世报 GitPython `Bad git executable` | 无 git | `set GIT_PYTHON_REFRESH=quiet`（`start-ai-api.cmd` 已设） |
| A绘世出图极慢（RTX 50） | torch cu118 | 升级 torch 2.7+cu128（A绘世内置 Python） |
| DSH 启动崩溃/会话损坏 | 是否动过 sessions 目录 | 用 E 盘备份恢复；不要在 sessions 树内重命名会话目录 |
