# 事件卡面板方案（7 天记忆第二窗口）

> 2026-10-27 · 目标：DSH 里只保留一个聊天窗口（最近 7 天上下文），另开一个「事件卡」窗口看/改事实卡与历史。
> 现状：第一个窗口已成立（重复会话已清理 + `archiveOrphanAgentSessions` 兜底）；事件卡目前只在 `<DSMP_MEMORY_DIR>\profile.md` 里，人看不见、改起来要手改文件。

---

## 1. 现状盘点

| 东西 | 在哪 | 现在谁能看 |
|---|---|---|
| 事实卡（事件卡） | `persona\profile.md`（897 字，模型 23:00 刷新） | 只有模型在会话首条 prompt 里看到 |
| 7 天原文 | `persona\raw\hot\<日期>\private_<OWNER_QQ>.jsonl` | `qq_memory_search` / `GET /api/socialV2/memory-search` |
| 交接摘要 | `persona\digests\*.md` + `state\memory.json` 的 handovers | 只在轮转时注入一次 |
| 桥接控制台 | `http://127.0.0.1:3100/`（`public\console.html`，单页 240KB，`data-view` 切页） | 有控制台令牌就能看 |

已有端点（都只认控制台令牌或 agent token）：

- `GET  /api/socialV2/memory-search?key=&q=&from=&to=&limit=`
- `POST /api/socialV2/memory-maintenance` `{"force":true}` → 归档 + 模型重写事实卡（返回 `profile.chars`）

缺口：**没有读/写事实卡的端点，也没有任何可视化页面。**

---

## 2. 三条路线

| | 方案 | 体验 | 工作量 | 要重启 DSH？ |
|---|---|---|---|---|
| **A** | 桥接控制台加「记忆与事件卡」页（`public\console.html` 加 `data-view="memory"` 一页 + 2 个新端点） | 浏览器里点开一个 tab，和现有控制台同一个壳 | **0.5 天** | 否（只重启桥接，10 秒） |
| **C** | 桥接单独出一个只读页 `/memory?token=`（老式仪表盘） | 另开浏览器标签，从开始菜单点开 | 0.25 天 | 否 |
| **B** | DSH 原生面板插件：`sidebar.panellist` 放一个图标 → 打开侧栏面板（`main` keyed slot） | 和 DSH 一体，最好看 | 1.5～3 天 | **是**（要构建 client 插件 + 重启 DSH） |

**推荐：先 A（顺手把 C 的入口保留为一个按钮），高频用了再上 B。**

理由：

1. A 复用控制台已有的令牌/CSRF/主题壳，没有构建链。
2. B 要写 Cordis host + client 两半：host 半读 `persona` 下的文件并暴露数据，client 半在 `sidebar.panellist` 注册按钮、在 `main`（keyed，已占 `conversation`）注册面板；client 插件改动要走 DSH 的构建产物，改了必须重启 DSH 才生效——期间 QQ 机器人会掉线重连，测试成本高。
3. A 做出来以后，B 的接口和数据模型可以直接复用（B 只是把 A 的页面塞进 DSH 的壳里）。

---

## 3. 方案 A 详细设计

### 3.1 后端（`src/bridge.js`，新增约 150 行）

**① `GET /api/socialV2/memory-profile`**（仅控制台；带 agent token 的请求 403）

```json
{
  "ok": true,
  "profile": { "chars": 897, "updatedAt": 1793..., "text": "..." },
  "bounds": { "today": "2026-10-27", "startDay": "2026-10-20", "windowDays": 7 },
  "days": [ { "date": "2026-10-24", "user": 20, "assistant": 35, "total": 55 } ],
  "digests": [ { "name": "...md", "createdAt": 1793..., "reason": "age", "mode": "model", "chars": 243 } ],
  "handover": { "exists": false, "consumed": true },
  "stats": { "hotFiles": 4, "archiveFiles": 0, "sessions": 1 }
}
```

数据来源：新包 `@local/deepseek-memory` 导出的 `memoryStats` / `windowBounds` / `readProfile`，加一个新函数 `dayCounts()`（遍历 `raw/hot/<day>/*.jsonl` 计数，最多 8 个日文件）。digests 用 `fs.readdirSync(dirs().digests)` 读头部 frontmatter（文件很小）。

**② `POST /api/socialV2/memory-profile`**（仅控制台）

- body `{ "text": "..." }`，要求 `text.length <= memory.profile.maxChars * 2`（默认 3000 字上限，防手滑贴整篇）
- 写前自动备份 `profile.md.bak-<yyyyMMdd-HHmmss>`，目录里只保留最近 5 份（多的删最旧）
- 原子写（tmp + rename），写后 `log('事件卡：控制台手动更新（N 字）')`
- 返回 `{ok:true, chars, backup:'profile.md.bak-...'}`

**③ 复用**：手动刷新事件卡 = 现有 `POST /api/socialV2/memory-maintenance {"force":true}`，不新增接口。

**④ 只读页 `/memory`（可选，方案 C 的入口）**：返回一个极简 HTML，只展示事实卡 + 每日条数 + 搜索框；链接到控制台 `/?token=...#memory`。

### 3.2 前端（`public\console.html`，新增约 250 行 HTML/JS/CSS）

- 导航：在「聊天行为」组末尾加
  `<button data-view="memory" class="nav-item"><span class="nav-icon">▣</span>记忆与事件卡</button>`
- 新 `<section id="section-memory" data-page="memory" class="card span-all">`，内容：
  1. **状态条**：`窗口 2026-10-20 起（今天 2026-10-27，共 8 个日文件）· 事实卡 897 字 · 更新于 14:52 · 会话 1 · 归档 0`
  2. **事实卡卡**：`<textarea id="profileText" rows="24">` 直接编辑，按钮「保存」「撤销修改」「恢复上次备份」；旁边小字「模型每天 23:00 自动重写；手改后以手改版为准」
  3. **7 天每日条数**：8 行小表（日期 / 主人 / <PERSONA_ALT> / 合计 / 点日期→跳到检索 from=to=该日）
  4. **最近交接摘要**：digests 列表（时间、reason、mode、字数），点击展开正文（新增 `GET /api/socialV2/memory-digest?name=` 或直接在 profile 端点里带前 3 篇正文——建议后者，省一个端点）
  5. **检索**：q + from + to + limit → `memory-search`，结果列表显示「日期 角色：片段」，最多 20 条
  6. **操作**：「立即日终维护」（`memory-maintenance force`，显示返回的 `profile.chars` 与 `archived`）、「刷新」
- 刷新策略：进入该页拉一次；页面可见时 30 秒轮询一次；其它页不轮询。
- 不动现有任何视图与函数，只追加 section + 一个 `renderMemoryPage()`。

### 3.3 安全

- 仅控制台令牌；沿用 bridge 现有 CSRF 校验（`application/json` + 同源 Origin）。
- 只能看/改**主人私聊**的事实卡（沿用 `memory-search` 的 key 限制）。
- 保存必留备份；不提供「清空日志」「删除归档」按钮。
- 事实卡内容当纯文本渲染（`textContent`），不 `innerHTML`，避免手改时写入 HTML。

## 4. 验收清单

1. `node --check src\bridge.js` 通过；桥接重启后日志有「7 天记忆已启用」。
2. 打开 `http://127.0.0.1:3100/` → 左侧出现「记忆与事件卡」。
3. 页面显示：窗口起点、事实卡字数（≈897）、8 个日文件计数（10-20 起，空日显示 0）。
4. 检索「擂饭」返回 4 条，点某条显示日期与片段。
5. 手改事实卡加一行 → 保存 → 目录出现 `profile.md.bak-*`，页面字数增加；再点「恢复上次备份」能回到原样。
6. 「立即日终维护」返回 `{ok:true, profile:{chars:...}, archived:...}`，日志有「长期记忆：事实卡已更新」。
7. 手机/窄窗口下页面不横向溢出（控制台已有响应式栅格，复用 `.card`/`.span-all`）。
8. 重启桥接后页面照常（不依赖内存状态）。

---

## 5. 排期与风险

- **A：0.5 天**（后端 2 小时 + 前端 2 小时 + 联调/验收 1 小时）。
  - 后端：2 个端点 + `dayCounts()` + `readProfile()` 导出（约 150 行）。
  - 前端：1 个 section + 1 个渲染函数（约 250 行，追加式）。
- 风险：
  1. `console.html` 是 24 万字符单页，改动只做「追加」，不重构现有函数；改完先用浏览器打开点一遍全部 tab。
  2. 事实卡被手改坏 → 备份 + 长度上限 + 「恢复上次备份」兜底。
  3. 桥接重启会让 QQ 机器人断 10 秒（reserved2 自动重连），选机器人不忙的时候做。

## 6. 后续（方案 B，可选）

- host 半：新插件 `@local/dsh-memory-panel`，`inject: ['http']`（或直接复用 bridge 的 3100 端点，client 半 `fetch`——但要给 3100 加 CORS `Access-Control-Allow-Origin: http://127.0.0.1:<dsh端口>`）。
- client 半：`sidebar.panellist` 注册「事件卡」图标（id/order/label），点击后 `main` 槽注册 key=`memory` 的面板，或 `shell.overlay` 抽屉。
- 代价：改 client 插件要重新构建 DSH Web 产物并重启 DSH；每次改样式都要重启，迭代慢。
- 建议：A 用满两周、确认每天都看，再投入 B。
