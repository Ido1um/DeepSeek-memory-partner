## 二、数据布局（`<DSMP_MEMORY_DIR>`）

```
hot/YYYY-MM-DD/private_<OWNER_QQ>.jsonl   最近窗口内的按日原文
archive/YYYY-MM/private_<OWNER_QQ>-*.jsonl 窗口外归档（只增不减）
digests/private_<OWNER_QQ>-<时间戳>.md     每次轮转的交接摘要
profile.md                              事实卡（模型提炼的长期事实）
state/memory.json                       会话起点/字符数/轮转次数/事实卡注入标记/去重
logs/bridge.log 等                       桥接日志（已从 state/ 迁到 logs/）
```

## 三、运行规则

- 窗口：今天 + 往前 7 个自然日（8 个日文件），更早的整目录进 archive。
- 日终：23:00 后的第一个维护轮次做归档 + 刷新事实卡；`lastDailyAt` 防重复；关机错过则下次启动 5 秒补跑一次（只补一次）。
- 轮转：`session.startedAt` 早于窗口起点 00:00（reason=window）或 tokens ≥ 60000（reason=tokens）；会话忙/有挂起消息/DSH 未就绪时延后。
- 注入：新会话第一条 prompt 注入「【长期记忆（事实卡）】+【7 天记忆交接】」；事实卡按会话只注入一次，交接摘要按 `consumedAt` 只消费一次（24h 内可 restore）。
- 检索：`qq_memory_search` / `GET /api/socialV2/memory-search`，只允许 `private:<OWNER_QQ>`，hot + archive 都查。
- 手动维护：`POST /api/socialV2/memory-maintenance`（仅控制台令牌）。

## 五、已知限制

- 轮转/归档挂在 10 分钟维护轮次上，最长晚约 10 分钟；持续聊天时轮转会顺延。
- 交接摘要素材上限约 600 条原文，超长会话只覆盖最近部分。
- 角色卡要求回答历史问题时带「<SELF>翻了聊天记录」来源，实测未强制执行（可选收紧）。
- 机器人倾向按日期区间扫日志而不是关键词，查跨度大时可能漏（可选收紧）。
- 新增/改动的 MCP 工具需重启 DSH 才可见；改角色卡不需要。
