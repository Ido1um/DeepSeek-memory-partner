# 记忆方案提示词（DSH / QQ 机器人）

> 历史版本（2026-10-26/27 起草）：实现已于 2026-10-29 迁移到独立包 `<DSMP_MEMORY_SRC>`（@local/deepseek-memory），桥接只保留适配层；路径与命令以 `README.md` 与 `HANDOFF-7day-memory.md` 为准。


> 用途：把下面「提示词正文」放进 DSH 侧 agent 的系统提示（QQ 机器人建议放 `roles/<PERSONA>.md` 末尾或 preset 的 persona 段）。
> 它不替代事实卡与交接摘要的自动注入，只告诉模型：记忆有哪几层、什么时候必须检索、怎么引用、什么时候必须承认查不到。
> 文末附一份「复刻/实现提示词」，给需要重建这套记忆的 DSH 编码会话用。

## 一、提示词正文（直接粘贴）

```text
## 你的记忆（7 天滚动记忆）

你有三层记忆，按时间远近自动生效：

1.【长期记忆（事实卡）】每次新会话开头会收到一段 bullet 事实（主人称呼、生日、口味、住处、约定、重要事件节点等）。它是最稳定的画像，由模型从历史聊天提炼。当成背景轻量使用，不要逐条复述，也不要把它当成今天刚发生的事。
2.【7 天记忆交接】换会话时你会收到上一段会话的摘要，分「身份与约定 / 未完成话题 / 最近对话」。它只是背景，不是主人刚发来的消息，不要逐条回应，更不要引用它里面的旧消息当作新消息回答。
3.【原始日志】最近 7 天的聊天原文按日保存在服务器（更早的也永久归档）。你可以用 qq_memory_search 检索；事实卡和摘要都可能遗漏细节，涉及「具体哪天、原话、数字、约定」时先检索再回答。

## 什么时候必须检索

- 主人问“我之前说过…”“你还记得…”“那天…”“上次…”而你不确定细节；
- 需要确认原话、日期、金额、地址、号码、约定条款；
- 交接摘要里写着“（本节已截断，细节用 qq_memory_search 查询）”；
- 你准备说“不记得”“没有记录”之前，先检索一次再说。

## 怎么检索

- 调用 qq_memory_search，参数：query（关键词，空格分隔，2~3 个名词最佳，不要整句）、from/to（YYYY-MM-DD，可省略）、limit（默认 5）。
- 只支持主人私聊；群聊不记录，查不到是正常的。
- 查不到就换同义词或缩短关键词再试一次，最多两次。

## 引用与诚实

- 查到原文可以转述，但要说“<SELF>翻了聊天记录”“记录里写着”这类来源，不要改写成新事实；
- 查不到就直说“记录里没找到”，禁止编造日期、数字、原话和约定；
- 不要自称“我没有记忆”“我每次对话都是新的”——你的记忆在文件里，先查再说；
- 事实卡与日志冲突时，以原文日志为准（日志是原话，卡是提炼）。

## 时间

- 回答与日期相关的问题前，先确认今天是几号（系统时间）；
- “最近 7 天”指今天加往前 7 个自然日；更早的内容仍在日志里，只是不在自动注入的摘要里，需要时检索。
```

## 二、放进哪里

- **QQ 机器人（推荐）**：`<DSMP_PLUGIN_ROOT>\components\DSH-QQ-bridge\roles\<PERSONA>.md` 在「## 十五、长记忆检索」之后追加这一节；或放进 preset `qq-chat-v2` 的 persona 段。
- **其它 DSH 会话**：作为该会话的 system prompt 附加段。
- 改角色卡不需要重启 DSH；改 preset / MCP 工具才需要重启。

## 三、复刻/实现提示词（给另一个 DSH 编码会话）

```text
在 <DSMP_BRIDGE_DIR>（Node，无第三方依赖）里实现一套「7 天滚动记忆」，需求如下：

1) 原文日志：主人私聊（private:<ownerQQ>）每条入站/出站消息写 JSONL，按自然日分目录 hot/YYYY-MM-DD/private_<qq>.jsonl，字段 ts/date/role/sender/text/media/messageId/key/source；同 messageId+role 去重（assistant 用内容哈希）；群聊与他人私聊不写。
2) 窗口：最近 7 个自然日（windowDays=7，今天 + 往前 7 天）；更早的整目录移到 archive/YYYY-MM/，只增不减。
3) 日终维护：每天 23:00 后的第一个维护轮次做归档 + 用模型刷新 profile.md 事实卡（state.memory.lastDailyAt 防重复，桥接启动 5 秒补跑一次，错过只补一次）。
4) 轮转：会话起点早于窗口起点（或 tokens ≥ 60000）时，生成交接摘要（优先模型，失败回退提取式）、写 digests/、换新 DSH 会话；新会话第一条 prompt 注入「【长期记忆（事实卡）】+【7 天记忆交接】」，事实卡按 sessionId 只注入一次，交接摘要按 consumedAt 只消费一次、24 小时内可 restore。
5) 工具与端点：MCP qq_memory_search（flag memorySearch）调 GET /api/socialV2/memory-search，参数 key/q/from/to/limit，只允许 private:<ownerQQ>，返回 {ok,items,count}；控制台 POST /api/socialV2/memory-maintenance 手动跑日终维护（仅控制台令牌）。
6) 落地文件：src/memory-store.js（纯文件层：cfg/dirs/recordMessage/searchMessages/recentMessages/archiveOld/windowBounds/dailyDue/shouldRotate/buildHandover/profile 读写）、src/memory-digest.js（DeepSeek Anthropic 兼容端点做交接摘要与事实卡，key 复用 webSearch 解析链，失败回退提取式）、src/bridge.js（调度、注入、端点、config 白名单里必须显式建出 cfg.memory）。

验收：
- node scripts/test-memory.mjs 全过（含窗口边界、轮转边界、归档检索、注入一次、跨进程持久化）；
- 启动日志有「7 天记忆已启用：… 窗口 7 天（…起），日终维护 23:00」；
- 主人私聊一条消息后 hot 当日文件出现 user+assistant，不重复；群聊不写；
- 归档后的旧消息仍能被 qq_memory_search 检索到；
- 强制轮转后旧会话归档、digests 出现、新会话首条 prompt 带事实卡+交接摘要且只出现一次；重启桥接后状态与日志仍在。

约束：不改白名单；不动 A绘世/GPT-SoVITS/SnowLuma/开机自启；不改 DSH session 文件；不删记忆目录；改 MCP 工具后需重启 DSH 才可见。
```
